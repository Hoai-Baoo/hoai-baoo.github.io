# Introduction

Modern chips such as SoCs, ASICs, and FPGAs usually contain multiple independent clock domains. Some run at high speeds like CPU cores, while others operate slower such as peripheral buses, memory controllers, PCIe, Ethernet, and similar interfaces.

Connecting signals directly between these asynchronous domains is dangerous. It can trigger metastability, where flip-flops become unstable and produce unpredictable outputs, often leading to system failures or subtle bugs that are difficult to debug.

An Async FIFO solves this problem by providing a safe and reliable way to transfer data between two different clock domains. The write side works on its own clock (`wclk`), while the read side operates on a separate clock (`rclk`).

### Key Components

- **Memory**: Typically a dual-port RAM with one write port and one read port.
- **Write Pointer**: Tracks the position for incoming data.
- **Read Pointer**: Tracks the position for outgoing data.
- **Full and Empty Flags**: Generated by comparing the pointers after synchronization.

---

### What Makes Async FIFOs Reliable

#### 1. Gray Code Pointers

Using regular binary pointers is risky because multiple bits can change at the same time. For example, when going from `0111` (7) to `1000` (8), all four bits flip simultaneously. During clock domain crossing, this can cause the other side to see incorrect intermediate values.

Gray code fixes this issue by ensuring that only one bit changes between consecutive values.

| Binary (Decimal) | Gray Code |
|------------------|-----------|
| 000 (0)          | 000       |
| 001 (1)          | 001       |
| 010 (2)          | 011       |
| 011 (3)          | 010       |
| 100 (4)          | 110       |
| 101 (5)          | 111       |
| 110 (6)          | 101       |
| 111 (7)          | 100       |

The conversion is simple:
```verilog
assign gray = bin ^ (bin >> 1);
```

> For any binary value bin[2:0]:

> `gray[2] = bin[2] ^ 0 = bin[2]`

> `gray[1] = bin[2] ^ bin[1]`

> `gray[0] = bin[1] ^ bin[0]`

## 2. 2-Stage Synchronizer:

The Gray-coded write pointer is synchronized into the read domain using two flip-flops, and vice versa. This technique significantly reduces the risk of metastability.

## 3. Full/Empty Generation:
- **Empty:** When synchronized write pointer == read pointer.
- **Full:** When synchronized read pointer is "one behind" the write pointer (circular buffer handling).

# Use Case

- Crossing data from high-speed to low-speed domain (or vice versa).
- CDC (Clock Domain Crossing) for bursty data.
- Elastic buffers in high-speed serial links.
- FPGA designs connecting different clock regions.
